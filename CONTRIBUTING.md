# Contributing to Vitamin C

Crate READMEs and Rust documentation are for library users. Put development
workflows, test infrastructure, and design history in repository documents.
See [documentation conventions](docs/documentation.md) for shared README
links and checks, and [RELEASING.md](RELEASING.md) for release procedures.

## Design records

The [architecture decision records](docs/adr) explain past design decisions:

- [Describe plaintext once and consume it with sinks](docs/adr/0001-describe-plaintext-once-and-consume-it-with-sinks.md).
- [Null equality terms and null placement in order spaces](docs/adr/0002-every-null-gets-an-equality-term-and-an-order-space-may-place-nulls-first-or-last.md).
- [A versioned storage profile for values that are kept](docs/adr/0003-a-versioned-storage-profile-for-values-that-are-kept.md).

These records retain their historical discussion and status. Crate docs
describe current APIs; [STORAGE.md](packages/aead-frame/STORAGE.md) defines
the storage format and its compatibility contract.

Stack's [encoding-domain decision](https://github.com/cipherstash/stack/pull/1139)
is a separate ADR 0002. The marker migration in
[issue #471](https://github.com/cipherstash/vitaminc/issues/471) moved the
text and bytes prefix into `vitaminc-ore` 0.7 without changing stored terms
or domain labels. The released `cllw-ore` adapter already added that prefix;
adapters must remove their own prefix when taking the new encoding. This
exception does not permit changing an existing stored encoding under its label.

## Tests

Install and start [LocalStack](https://github.com/localstack/localstack) for
the KMS integration tests, then run `cargo test` from the repository root.
Node.js must be on `PATH` for the Node binding tests.

`packages/aead-frame/tests/conformance.rs` checks the shared
`testdata/value-conformance.json` corpus against the Rust codec. Node, Go,
and the WASM guest consume the same vectors, including host-specific
projections. `tests/legacy_fixture.rs` checks ciphertexts from the legacy
`Value` path against the current decoder.

The storage tests in `packages/aead-frame/tests/storage.rs` check values,
refusal classes, and typed reads against `testdata/storage-v1.json`. The
independent reader in `tests/support/reference.rs` checks the implementation
against the specification. Existing corpus rows must not be edited or
removed; new rows may be added. Run `mise run storage:corpus:check` to check
that constraint, which CI also enforces. Other language implementations
must match the corpus's values, refusal classes, and supported typed reads.

`cargo test -p vitaminc-aead-napi` runs Rust tests and builds a standalone
addon for the README example and Node suites: value conformance, object
safety, scalar-kind inventory, and encryption. The addon has a separate
Cargo workspace so `napi/noop` cannot stub its Node symbols. The test
harness rebuilds it from source during mutation runs. Functions exercised
only inside the addon have named exemptions in `.cargo-crap.toml`, because
`cargo llvm-cov` does not measure their coverage there.

AES-256-GCM known-answer tests compare native AWS-LC, native RustCrypto,
and RustCrypto compiled to `wasm32-unknown-unknown` and run in Node. The
`vitaminc-encrypt` feature `_test-rust-crypto-backend` selects RustCrypto
on native targets for these checks. It is not an application feature.
The `test-support` features in `vitaminc-aead` and `vitaminc-ore` expose
internal helpers; they are not supported application APIs. ORE helpers
check that scheme terms depend on the key and salt, including empty inputs.

Each equality normalization domain has an independently calculated HMAC
test vector in `packages/hmac/tests/normalized_equality.rs`.

The ORE integer and float encodings are checked byte for byte against the
pinned `orderable-bytes` 0.2.1 test dependency. Its Unicode case-folding
table is generated by `tools/generate_casefold.py`, which is not packaged
with the published crate.

## Compatibility checks

Each crate's manifest `rust-version` is the source of truth for its MSRV.
Dependency updates must respect it. CI checks the locked dependency graph
at those versions, native builds, encryption on `wasm32-unknown-unknown`
in Node, and the separate guest on `wasm32-wasip1`. See
[RELEASING.md](RELEASING.md) for documentation and CI synchronization.
